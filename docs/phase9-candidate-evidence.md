# P09-W04: candidate and scenario research evidence

The candidate route now reads the persisted candidate identity, the latest 200 evaluations and the selected scenario. It implements the frozen P04 research drawer contract in both appearances: historical outcome frequencies with numeric text, expected/percentile R, resolved regime and sampling fallback, and a keyboard-accessible methodology/provenance dialog. The safety label remains `Research only — not an order`.

`GET /api/research/candidates/{id}` returns the existing immutable provenance record behind operator authentication (404 for an absent record, 400 for a non-positive ID). Reading does not run a scenario or establish order eligibility. Existing evaluation and scenario endpoints remain authoritative. No migration or change to evaluation methodology is introduced.

The route controller owns queries, selected evaluation, research parameters, request lifecycle and dialog identity above the experience boundary. Evaluation is an explicit authenticated POST. Bounds mirror the server; dates are explicitly IST, converted to UTC, and cannot exceed the stored cutoff. Defaults are editable research assumptions, not recommendations. A seed is retained across appearance changes; matching successful scenarios may be reused by the backend. An optional backtest linkage is displayed from stored evaluations when present; this screen does not invent or automatically select a compatible backtest.

Before showing statistics, the projection checks candidate/evaluation/scenario IDs, scan, instrument, exchange/symbol, strategy/config version, interval, prices and history/cutoff boundaries. Non-successful scenarios, non-finite/invalid probabilities and inconsistent percentile ordering show an unavailable state. Probabilities are never normalized to hide inconsistent source results. The dialog also exposes stored catalogue/fingerprint/candle identity and cost assumptions. No order, approval or trade action belongs to this screen.

Browser evidence covers both appearances, mobile width, shared form continuity, an explicit reproducible request, provenance dialog, key clearing, invalid history/block bounds, empty history, failed scenarios and rejected provenance/probability values. The existing route and full browser suites remain regression coverage. PostgreSQL `ScenarioResearchApiIT` covers candidate read authentication, stored provenance, absent/invalid IDs and zero simulation side effects. Fixture-backed browser coverage is not connected-backend E2E certification.

The mobile header wraps its controls when necessary so appearance, credentials and runtime controls stay reachable; the candidate test identified an eight-pixel overflow at 375px before this fix.
