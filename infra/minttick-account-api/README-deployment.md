# Runtime deployment contract

This separate account host runs three containers on one isolated Docker network:
`postgres:16-alpine` (encrypted EBS-backed Docker volume), Java 21 account-only backend (immutable ECR commit-SHA image), and `caddy:2.10-alpine` with TLS/ACME. Only Caddy publishes ports 80/443. The host has no SSH and is managed through SSM.

The reviewed `deploy_account.sh` script must execute as root on the account host with exact AWS account ECR URI, branch-reviewed Git SHA and owned domain. It uses the existing password generated by the host's bootstrap. No password is transferred to GitHub. Backend and PostgreSQL are on an internal Docker network. The service is *not* assumed live merely because containers start: the script tests authenticated TLS readiness and the protected unauthenticated Cognito endpoint.

## Before deployment

1. Apply `main.tf` in account `098859530205` with an approved Route53 zone and the intended account hostname. The paid-resource gate is explicit.
2. Review/create an OIDC role restricted to ECR uploads and SSM command execution on the new host. Do not reuse the Cognito OIDC deployment role.
3. Build the backend image from a trusted `dev` commit SHA for `linux/arm64`; push it to the dedicated immutable ECR repository.
4. Execute `deploy_account.sh` through the narrow SSM deployment role, with output sanitized; never print passwords or tokens.
5. Validate `https://<domain>/actuator/health/readiness` and that `/api/auth/cognito/me` returns 401/403 unauthenticated; reject trading/admin paths.
6. Generate a real APK with the verified API URL and Cognito public configuration, then test an actual signup and email confirmation on device.

This is a new paid EC2 endpoint, **not** the PAPER host. Account data requires independently scheduled encrypted off-instance backups with restore tests before production use. The prototype is for limited development testing only.

The deployment workflow is deliberately not permitted to run until an AWS role with narrowly scoped permissions is bootstrapped. Public DNS ownership is a hard prerequisite for trusted device HTTPS.
